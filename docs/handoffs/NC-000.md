Default CMake options are `PIRANHA_ENABLED=ON`, `DISCORD_ENABLED=ON`, and `DTV=OFF`.

## Build and test status

### Existing documented Windows build

Run from a Visual Studio Developer PowerShell with CMake and required dependencies available:

```powershell
git clone --recurse-submodules https://github.com/Dziuras98/engine-sim.git
cd engine-sim
git checkout agent/nc-000-repository-bootstrap
git submodule update --init --recursive
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

### Existing CI build

`.github/workflows/cmake.yml` triggers for pull requests targeting `master`, uses `windows-latest`, initializes submodules, installs/caches Boost 1.78.0, configures CMake, and builds the Release configuration. The workflow does not currently execute CTest.

## Known limitations and risks

- The current project documentation states that the application build is Windows-only.
- The existing CI workflow builds but does not run `ctest`; NC-001 should decide whether test execution belongs in the repeatable baseline.
- The project depends on recursive Git submodules and configure-time network access for GoogleTest.
- The Discord RPC path imports a bundled Windows library, which may constrain toolchain/architecture choices.
- `test/` and `tests/` now coexist by design; future agents must not silently migrate existing tests.
